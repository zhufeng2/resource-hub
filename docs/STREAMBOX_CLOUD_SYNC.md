# Resource Hub 账号同步与 StreamBox 续播

## 用户行为

登录现有 Resource Hub 账号后，收藏、观看记录和续播进度自动绑定账号。首次升级登录时迁入已有本机收藏与观看记录，只迁入一次；后续不同账号使用独立本地副本，退出账号清空当前界面的账号记录，已排队操作保留在原账号。

“我的 → 账号云同步”显示状态，点击可以手动同步。收藏/删除/观看修改先保存本地，约 800ms 后推送；应用存活时每分钟补同步，回到前台也请求同步。进度在播放中每 30 秒、暂停、结束或退出播放时保存并排队。进程被系统直接终止时，不保证最后不足 30 秒的进度已保存；进程完全退出期间没有独立系统后台任务，重新打开会补传。

从记录续播时先尝试同步账号最新状态，网络不通则沿用本机进度。恢复实际影片、个人 fid、选集来源、位置、时长和完成状态；新设备可从已有个人目录重建本机选集，不重新转存。播放 Cookie 和临时播放地址不上传。

跨设备播放需要当前设备绑定同一夸克网盘账号，并且原文件仍可读取。不会把一个夸克账号的文件 ID 当成另一账号的可播放文件。文件移动或删除时仍需核对资源。

## 服务端升级（必须）

本轮已修改本地客户端及服务端源码，尚未部署线上。只安装 APK 不会让旧服务端具备云同步能力。旧服务端会在同步状态显示“服务端尚未启用云同步，请更新后端”。

更新包 `StreamBox-0.8.6-server-update.zip` 包含：

- `backend/store.py`
- `backend/library_sync.py`（新增）
- `web/app.py`
- 本说明

将包内代码按相同路径合并到与本项目兼容的服务器源码目录。保留服务器的 `.env`、数据卷、SQLite 数据库和密钥；先按 `backend/README.md` 备份数据库及密钥，再在项目根目录执行：

```sh
docker compose -f backend/compose.yaml up -d --build app
```

启动时自动创建 `media_library`、`media_library_versions` 和索引，不修改原用户、搜索记录或额度。没有新增依赖和必填环境变量。使用其他 Compose 文件的部署按其现有方式重建 app 服务。

更新后在两台设备登录同一 Resource Hub 账号，等待“已同步”；一台收藏或播放后暂停，另一台打开收藏/观看记录并续播。实际双设备和线上网盘读取仍需验收。

## 协议与冲突处理

- `GET /api/library?after=<revision>`：按当前会话用户返回增量，每页最多 100 项；包含删除标记。
- `POST /api/library`：最多 10 个变化，客户端按约 12KB 分批；字段为 `kind/id/base_revision/mutation_id/deleted/data`。
- 使用原网站会话、同源 Origin、CSRF、速率限制；用户 ID 只取已登录会话，不接受客户端指定目标账号。
- 每次修改有唯一 mutation ID 和基础版本。响应丢失可重试，相同操作不重复增加版本；上传期间新的本机修改继续保留队列。
- 收藏和删除采用版本核对；遇到冲突保留服务端已确认状态，状态栏说明已合并云端记录。观看进度可用较新播放事件时间合并旧基础版本，向未来偏差超过五分钟的事件时间以服务器时间约束。
- 删除记录持久保留为墓碑，旧离线副本不能靠后到达的进度或收藏操作复活它。重新收藏需在看到最新删除状态之后产生新修改。
- 每账号最多 2000 个同步条目（含墓碑），客户端观看展示保留最新 20 部、续看关联最多 200 部。新增达到上限时明确失败，不静默丢弃旧操作。
- 元数据只允许影视资料、分享引用与个人文件/目录 ID、位置、时长等固定字段。拒绝 Cookie、签名媒体 URL、任意主机图片或额外字段。分享提取码不上传。
- 对超过 100 个顶层条目的选集，只同步既定个人目录引用，新设备有界读取该目录恢复选集；小目录额外保留原顶层 fid 集合。
- 删除 Resource Hub 用户时同时删除对应同步表及游标记录。
